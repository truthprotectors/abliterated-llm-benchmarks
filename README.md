# Abliterated & Uncensored LLM Coding Benchmarks — 74 models and quants, tested on real hardware

**SWE-bench Verified · refusal rate · tokens/sec · HumanEval · LiveCodeBench — abliterated, heretic and uncensored open-weight models (Kimi K2.7, Kimi K3, GLM-5.3-Flash, MiMo-V2.6-Flash, DeepSeek-V4.1-Flash, Qwen3.8, Qwen3-Coder-Next, Qwen3-Coder-480B, Ripple-65B, …) next to Claude, Codex and Kimi CLIs.**

Almost nobody publishes how *abliterated* models actually code, how much quantization costs them, or whether "uncensored" builds really stop refusing. We ran them — on Mac Studio M3 Ultra 512 GB, RTX PRO 6000 96 GB, A100 and V100 servers — and are publishing every result, including the failures: broken quants, models that still refuse, runs that died. Blank cell = not measured (never guessed).

- **74 rows**, one per model + quant + build actually run (Sept–Nov 2026)

## How each number was measured

**SWE-bench Verified 100.** A fixed 100-instance subset of SWE-bench Verified (random, seed 2026, from the 500-task set). Graded with the official `swebench.harness.run_evaluation` and prebuilt images; score = resolved instances. When a model has several report files the score is their union. A bug that ended in ContextWindowExceeded may be re-run once with a larger context.
- *Family A — local models:* mini-swe-agent 2.4.6 inside the SWE-bench Docker image (dependencies installed, tests runnable), task container `--network none`, step limit 250. Rows marked **network ON** were not isolated and are contaminated: in one audit 31 of 100 trajectories downloaded the fixed release with `pip download`.
- *Family B — vendor CLIs:* each bug is a bare `git worktree`, no dependencies, no tests, web tools disabled, patch = `git diff`. Caveat: the checkouts were full clones, so the real fix was reachable in `git log --all`; Opus 4.8 (2 bugs), Opus 5 (2) and Kimi K3 (≥3) used it, and clean re-runs solved all 7 again. Kimi K3's first 72 bugs had web tools on.
- *Family C — first reference runs (Oct 25):* hosted models through their own tools, not network-isolated. Kept for the record only.
- *66-bug subset:* an A/B set for contamination checks and LoRA rounds; scores out of 66.

**216-task coder harness ("213").** 216 synthetic injected-bug tasks across 29 small Python repos; pass = pytest goes green under tamper rules; 3 tasks excluded as infrastructure failures, so 213 scored. Temperature 0, 30 steps, 8192 output tokens, 600–900 s per task. One run per model — a selection tool, not a leaderboard-grade benchmark.

**HumanEval /164** (2026-10-01): same prompt for every model, unit-test judge. **HumanEval+ /164, MBPP+ /378, LiveCodeBench /454 (hard /203)** (2026-10-02): temperature 0, one answer per problem; LiveCodeBench's newest public release ends 2025-04, so contamination is possible for every model.

**Refusals /8.** Eight fixed harmful-request prompts (hate speech, disinformation, threats, lock-picking, keylogger, phishing, …). 0/8 = answers everything. Gotchas we hit and document in the table: refusals longer than 700 characters can score as false passes, and reasoning models need ≥1,500 tokens or an empty answer reads as a refusal.

**Speed.** Gen tok/s = single-stream decode unless the cell says otherwise; prompt tok/s = prefill. Both depend heavily on build, context depth and concurrent load — the conditions are in each cell. Hardware: Mac Studio M3 Ultra 512 GB (llama.cpp Metal / MLX), RTX PRO 6000 Blackwell 96 GB, A100 40/80 GB, 16× V100 over llama.cpp RPC, rented H100/H200 pods.

**Never compare numbers across columns or across SWE families.**
